## 一、执行质量评估（对照 PROJECT_SPEC 验收标准逐条核对）

### 总体结论

主线路 M0–M5 已经按里程碑逐个落地，每个里程碑都有独立提交、复查文档
（`docs/M*_REVIEW.md`）、单元测试与模拟器端到端记录；过程中 E2E 揪出并修复了

### 已知的工程瑕疵（评估时发现）

1. M5 提交信息正文混入一个字面 `\u0000`（shell 引号问题，只影响日志观感，不影响代码）。
2. 弹幕屏蔽词过滤只有单元测试，模拟器上受点击坐标限制未完成 UI 级验证。
3. **LK 凭据存于 Hive 明文 KV**——规格 C1 要求安全存储等价物，属安全缺口，建议排 P1。
4. 备份包含已下载正文时体积会明显变大，导出侧还缺「包含离线内容」开关。

## 三、任务分配

按环境能力分工：**dpsk 没有设备环境，负责纯代码 + 单元测试层；
我这边有模拟器，负责 UI 接线、夹具扩展、APK 构建与端到端验证。**

### 分给 dpsk（纯代码，无需设备）
| 任务 | 内容 | 交付标准 |
|---|---|---|
| D1 追踪客户端 | Bangumi REST（token 鉴权、收藏/进度读写）+ AniList GraphQL 客户端；错误分类对齐 `SourceErrorType` | 单测（假 HTTP）覆盖鉴权失败/404/超时；不碰 UI |
| D2 追踪上报服务 | TrackBinds 表读写、本地进度→远端映射、冲突策略（较新者胜） | 单测覆盖映射与合并；不碰 UI |
| D3 LNS SignalR 协议层 | 移植 Mixn 的 LightNovelShelfProtocol/SignalR 握手与消息帧 | 单测用录制帧回放；不能联调的接口留明确 TODO |
| D4 LK 账号域接口层 | 资料/轻币/签到/消息/评论的 API 封装与解析 | 单测（夹具 JSON）；解析兼容多候选键 |
| D5 JS 沙箱引擎 | flutter_js 接入、JS 规则格式（对齐 Miru 思路）、声明式双轨注册 | 单测跑通一条 JS 规则全流程（发现→详情→正文） |

### 分给我（设备环境：UI / 夹具 / E2E）
| 任务 | 内容 | 交付标准 |
|---|---|---|
| W1 追踪账号页接线 | 追踪账号页（绑定/解绑/状态）、进度上报触发点接入播放器与阅读器 | 模拟器 E2E（假 token + 夹具 Bangumi 端点） |
| W2 夹具扩展 | 夹具服务补 Bangumi/AniList 追踪端点、LNS 假握手、弹弹play 发送回执 | 端点自测脚本 |
| W3 JS 沙箱设备验证 | T2b 在模拟器跑 JS 规则全流程 | 截图 + 复查记录 |
| W4 阅读器增强 UI | 音量键翻页/屏幕常亮/插图放大保存/界面字号/G2 全标已读 | 模拟器 E2E |
| W5 安全硬化 | 凭据迁移 flutter_secure_storage + 旧数据迁移 + 登出清理 | 单测 + 模拟器验证 |
| W6 账号域页面 | LK 资料/签到/消息/评论页面 | 模拟器 E2E（需账号则留待联调） |
| W7 真机验收 | 视频合成/性能/权限/WebDAV 双设备 | 需真机，单独排期 |
