## 1. 范围与结论

用户指定先前第一轮的后两项：

1. 播放器音轨选择、字幕时间/显示校正。
2. 漫画宽页拆分、双页错位校正。

不包含小说全文搜索，不恢复此前移除的功能，不调整已经通过手机验收的双指仲裁与夜间模式。评估面向Android/Windows，iOS独立工作区不计入承诺。

结论：漫画布局项收益更确定，纯Dart部分可复用现有图片渲染。播放器项为条件性增强：音轨/字幕是否可选由实际媒体决定，Android字幕时间校正需先验证时间轴接入方案，不能仅靠菜单承诺双端等价。

## 2. 来源真的有可选音轨和字幕吗

### 2.1 已核实的Triomi现状

- `lib/core/models/chapter.dart::PlaySource`目前保存线路名称、URL、请求头、网页解析标记、格式等，没有独立音轨或外挂字幕清单。
- `player_page.dart::_pickSubtitles`读取Android `subtitleTracks` 或Windows `player.state.tracks.subtitle`，枚举的是当前解码器发现的轨道，空时已提示没有可用字幕轨。
- Android `NativeVideoPlatformView.kt`使用Media3 1.9.4；`setUrl`当前只建立视频MediaItem，没有传入外部SubtitleConfiguration；文本cue输出到SubtitleView。
- Windows使用media_kit/mpv。网页解析得到视频请求，不等于同时接收网页JavaScript播放器的独立字幕配置。
- 本次没有逐站逐集重取流或统计轨道数量；历史实播和“画面上看见字幕”不能证明字幕是独立轨道。不能宣称当前某站一定有多音轨，也不能宣称所有来源都没有。

### 2.2 对用户承诺的条件

| 媒体实际情况 | 可以提供什么 | 不可承诺什么 |
|---|---|---|
| 只有一条音轨 | 显示当前音轨信息 | 不能生成另一语言配音；换线路也不等于切音轨 |
| 容器/HLS主清单包含多个可解码音轨 | 枚举并选择实际音轨 | 媒体后缀本身不保证多轨；没有语言标签时不能猜语言 |
| 有内嵌或HLS声明的软字幕 | 切换/关闭轨道；对支持格式校正时间与样式 | 不能保证每种位图/特效字幕均能改字号、改位置 |
| 中文字幕烧录在视频画面中（硬字幕） | 原样播放；必要时叠加用户外挂字幕 | 不能关闭/移动/改字形/校正烧录字幕，也不能凭无轨道反向证明一定是硬字幕 |
| 网页单独加载字幕，但媒体未声明 | 经来源明确提供并安全传递后可接入 | 仅嗅探视频URL不能自动获得这些字幕 |
| 用户自行选择SRT/WebVTT文件 | 独立加载、选择、时间/基础样式校正 | 不代表本站原来提供字幕；不自动在线找字幕或绕过权限 |

经验判断而非本站实测结论：网页压制资源常见单音轨配烧录字幕，因此“选轨菜单”未必是现有在线播放来源的高频收益。必须先看真实轨道，再决定界面显示；用户外挂字幕是另一条独立可用路径。

## 3. A项：音轨选择与字幕校正

### A0. 实施开始后的首个验证关口

- 受控媒体覆盖：单音轨无字幕、两音轨+两文本字幕、HLS主清单带外置音轨/字幕、用户SRT/VTT、烧录字幕但无软字幕、位图/样式字幕。
- 对用户关心的已启用来源，有限抽样最终播放器发现的轨道及格式；只报告该来源/线路/集数样本，不推断全站。样本URL、Cookie、签名参数不得写入报告或日志。
- 核对解析器是否保留主清单；若传入的已是单一视频子清单，不能假装能枚举主清单里丢失的其它音轨。
- 区分准备中、已准备但零轨道、轨道不受支持与真正的读取错误。失败不写成“没有字幕”。
- 此阶段需要用户“开始做”后才执行；本次没有启动以上运行验证。

### A1. 产品行为与范围

- 在现有播放设置增加音轨入口，字幕入口整合轨道、外挂文件与校正，继续使用当前可滚动子菜单模式，不堆叠多个弹层。
- 显示自动选择、当前选择、语言、名称及可解码状态；音轨只有一条时说明仅此一条，不展示虚假语言选项。未知语言显示“未标注”。
- 字幕关闭只关闭播放器渲染的软字幕，不声称关闭画面中的烧录字幕；提示“当前未发现独立字幕轨”，不凭此断言字幕类型。
- 时间校正用明确文案“提前/延后”，建议初始范围±10秒，步长0.1秒，可复位；正值表示延后。它不能修复帧率或剪辑差异导致的持续漂移。
- 基础样式提供字号倍率与安全区内垂直位置；保留“使用原字幕样式”与“使用阅读者样式”的区别，不能直接压平所有ASS定位/位图内容。
- 外挂字幕初始完整支持用户选择的SRT/WebVTT；不做在线字幕搜索下载、自动翻译、语音生成、双字幕或更换视频引擎。其它格式保持原引擎能力且明确能力限制，不能误报全支持。

### A2. 状态与持久化

- 全局保存音轨/字幕语言偏好、字幕样式默认值，跨集按语言/角色重新匹配；不把本集的`group:track`序号用于下一集或换源。
- 字幕提前/延后属于具体媒体版本的校正，默认仅当前播放会话有效，换集/换线路复位；用户显式“记住当前视频校正”时才按来源、作品、剧集、线路/媒体版本及字幕内容指纹存储。不把带token的URL作为持久键，也不跨站套用偏移。
- 外挂字幕通过系统文件选择器读入私有受控副本，限大小并检查编码/格式，显示能撤销的加载状态；不能把文件授权丢失当加载成功。恢复或同步时缺文件给出重新选择入口，不传输原设备路径。
- 引擎轨道快照与选择操作绑定本次媒体generation；切集、重试、后台回前台出现晚到结果时丢弃。轨道变化由真实事件更新，不仅打开菜单时读取一次。
- 记住偏好不等于已经应用，只有引擎实际选择结果确认后显示为当前选择；不支持轨道明确禁用并解释。

### A3. 双端技术路径

| 部分 | Android / Media3 1.9.4 | Windows / media_kit+mpv |
|---|---|---|
| 音轨 | 复用`currentTracks`及`TrackSelectionOverride`，补音轨列表、选择与`onTracksChanged`通知 | 复用真实audio tracks及setAudioTrack，监听媒体切换与轨道变化 |
| 字幕列表 | 保留已有文本选轨功能，增加当前选择、语言、角色/格式、支持状态 | 保留现有subtitle tracks，统一显示语义 |
| 字号/位置 | SubtitleView及Cue样式，检查内嵌样式/line定位对覆盖的影响 | mpv字幕属性；先核实固定二进制和media_kit是否启用了原生/Flutter哪条渲染路径，避免双重渲染或设置不生效 |
| 外挂字幕 | MediaItem.SubtitleConfiguration，验证content URI/私有副本、重新准备时的续播位置 | SubtitleTrack.uri/现有引擎加载通路，核实编码与路径安全 |
| 提前/延后 | **主要技术风险**：须在cue解码/调度时间轴之前正确偏移，支持提前读取及seek重置 | mpv sub-delay等属性；若当前用Flutter字幕层，必须贯通同一时间校正语义 |

Android时间校正不能通过`onCues`后挂Timer冒充：只可延后不能真正提前，seek后会留下旧cue；也不能通过音视频整体seek假装只调整字幕。固定版本TextRenderer是final类，没有直接可套的通用字幕延迟setter。实施时先验证受控的字幕时间轴变换/renderer组合方案与格式覆盖，保留同一ExoPlayer/MediaSession。对SRT/VTT可评估保留原始cue并生成偏移时间轴；内嵌/HLS字幕必须单独验证采样、缓冲和时间偏移边界，不能假定与外挂文件等价。禁止直接fork整个播放器、启用已弃用的legacy路径或复制一整份上游TextRenderer来绕过评估。若无法在当前依赖上可靠实现完整双端范围，先报告具体受限格式和方案，征求范围调整，不能静默只做Windows后宣布完成。

### A4. 预计改动边界与验收

- `player_menu.dart`：音轨与字幕设置呈现；`player_page.dart`：选择/状态/会话生命周期；`data/player_settings.dart`或已有偏好仓储：全局偏好及明确作用域。
- `NativeVideoPlatformView.kt`及Dart controller：新增真实选轨/字幕校正方法及状态事件。不得改变音量控制、PiP/后台同player所有权、现有续播与来源请求头隔离。
- 仅在来源确实提供独立字幕时，扩展`PlaySource`/resolver的显式字幕描述与完整序列化；不是第一步就重写规则协议。跨域字幕不能自动带视频Cookie/Authorization，遵守代理、TLS及重定向隔离。
- 验收：真实听到音轨切换；无多轨/不支持轨道提示准确；软字幕关闭确实消失；硬字幕不受设置误导；提前与延后在seek/暂停/倍速/换集后仍正确；样式真图；外挂字幕授权/乱码/缺文件；退出后不影响下一视频。测试覆盖消费者结果，不只断言菜单或通道调用。
- HLS离线下载目前拒绝不完整外部音轨，不因为在线播放选轨而放松完成判定。本项不自动承诺离线保存所有语言和字幕。

## 4. B项：漫画宽页拆分与双页校正

### B1. 产品行为

- 所有持久阅读偏好仍是全局漫画设置，写入既有`reader.manga`，不恢复每作品设置覆盖。
- 新增宽页策略：不拆分（默认，兼容旧体验）/自动识别后按阅读方向分半。提供当前图片会话内“拆分/整图”修正入口，不默认记成每书偏好。
- 自动判定只用图像有效宽高比，是“横向图片候选”而非真实两页检测。初始候选阈值例如宽/高≥1.25仅为待实图验证的提案，不能视作已定算法；彩色横图/跨页大插画也可能命中，用户可关闭。
- 双页对齐为0/1两种配对起点（第一张参与配对 / 第一张单独作封面），默认保留现状；既有宽600逻辑不变，只有双页生效时显示校正入口。可提供当前章会话内翻转对齐，换章后继承全局值。
- 未拆分的横向整图在双页模式下单独占满一屏，前后不硬塞空白配对；拆开的两个半页在宽屏双页中允许相邻配对，防止破坏整图阅读顺序。
- 条漫保持连续完整图片列，不套分页式拆半/封面对齐，不把长条图错误识别成双页；设置面板明确适用模式。竖向分页按上/下翻页，分半先后仍由全局LTR/RTL或显式半页顺序决定，不由屏幕物理左右位置猜测。

### B2. 布局模型与身份

- 原始图片清单不修改。新增纯布局映射：原图索引、区域（整图/左半/右半）、组合成的屏幕/spread；逻辑显示页与源图片页是两种坐标，不能继续仅用`index * _spreadSize`。
- 渲染顺序：取得并验证图片尺寸→按有效图像区域决定整图/拆半→生成左右区域→配对→适配→缩放/夜间遮罩。对裁边需明确图像坐标换算，不先裁掉内容再按旧坐标分半。
- 原始图第5张拆为右半/左半时，页码仍显示“5/N·右/左”（或先/后半），不把虚拟页数冒充来源总页数。宽屏显示组合原图范围；下载总数也仍是源图片张数。
- 双指操作继续由0.16.1已验收的外层`MangaZoomView`独占仲裁；不在半页内部叠加新GestureDetector抢捏合。翻页/切布局复位当前zoom，但保留原图+可见区域锚点。

### B3. 解码、加载与缓存

- 共用原图的ImageProvider和解码缓存，以sourceRect渲染半页，不生成两张磁盘图片，不改下载清单、SHA256或原文件。
- 通过尺寸元数据/现有解码回调逐步形成布局，不为检测尺寸提前全章解码；缓存图像信息按正确的源身份和内容revision更新。
- 当前代码ResizeImage的宽度除以spreadSize；拆半后若照搬会降低半页清晰度，需按真正显示比例计算有界decode尺寸，仍遵守宽2400/高8192和缓存预算，不用无限提高分辨率修清晰度。
- 图片尺寸晚到、裁边晚到、下载追加页面和旋转会改变布局；用原图+区域锚点重建，不按当前虚拟页号恢复，不在用户捏合进行中突然跳页。失败图保留稳定占位、重试和真实进度，不批量猜所有图片宽高比。

### B4. 进度与已读：本项最重要的正确性门槛

- 既有history中的漫画position仍保留原图index语义，不把虚拟半页序号写入，也不偷偷把0.5当左右半页而改变备份/同步契约。
- 若要重启恢复到同一半页，增加可选显示区域锚点（source/item/chapter+原图index+区域及revision）；位置源身份沿用现有复合键。实施前选择最小的持久字段扩展，连同Drift迁移、备份导入导出、WebDAV字段冲突策略和旧备份降级一并设计。
- 原图进度不变但由右半变左半时也需保存区域锚点，不能被现有按chapter/page去重吞掉；旧备份缺区域按阅读方向恢复该原图的第一半，不复活过期区域。
- 最后一张原图如果拆半，必须读到第二半才按现有可读完成规则标章节已读；不能把“到了最后原图index”当作“两半都看完”。显式批量标已读保持原业务语义。
- 切方向、关闭拆分、换成双页/条漫、缩窗/旋转应确定映射回同一原图；不会多报章节、把半页上报成两章，或改变远端追踪进度。

### B5. 预计改动边界与验收

- 新的纯Dart页面区域/spread映射组件，替换`manga_reader_page.dart`中固定spreadSize换算，统一触摸翻页、键盘、滑杆、章节末尾、恢复路径。
- `manga_page_image.dart`：共享原图、区域绘制和尺寸通知；`manga_reader_settings.dart`/sheet：新增全局策略；按B4需要扩展现有进度/备份契约，不另做平行书架模型。
- 不改`manga_zoom_view.dart`已批准的手势阈值与仲裁规则，不改夜间亮度算法，不重写网络图片/来源协议。
- 回归矩阵：LTR/RTL/上下分页，封面有/无，奇/偶页，横图位于开头/中间/结尾，连续横图，宽图不拆/拆半，双页对齐0/1，裁边组合，图片延迟失败和重试，离线/局部下载追加，旋转和窄宽切换，重启同半页，旧备份恢复，最后原图第一半不得提前完成，原有双指晚落/剩余指/缩回最小回归。
- 实际界面验收需Android与Windows实图，对比未拆整图、两半先后、封面对齐和缩放；仅布局数学测试不能代替目视。

## 5. 推荐执行顺序与批准边界

建议先做B项（漫画布局）的纯映射和进度契约，再集成渲染并保护手势；A项先完成A0能力抽样与Android字幕时间轴验证，再定具体实现。两项共享的只是发布流程，不需要为它们引入通用抽象层。

这份大纲不等于开发授权。当前只记录推荐默认值与待验证风险，尤其不能提前承诺某来源有多音轨、任意字幕可调整或所有扫描宽页都能正确自动识别。用户明确说开始后，才新增测试、编写功能、运行技术验证与编译试用；是否推送发布另按当时用户授权执行。
