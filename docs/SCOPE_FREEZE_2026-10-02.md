# 范围冻结与后续批次（2026-10-02）

## 目的

Triomi 是聚合器，不是 Kazumi、Komikku、Mixn 的逐项复刻仓库。参照项目只提供能力边界、交互原则和协议研究材料；每个功能必须先证明服务于 Triomi 的三类内容闭环，才进入实现计划。

## 已冻结的首发范围

- **番剧（Kazumi 参照）**：规则来源注册、发现/搜索/时间表、详情与多线路播放、历史/收藏、倍速/硬解入口、弹幕读取与手动匹配、WebDAV 备份。DLNA、一起看、Anime4K、弹幕发送和后台持续播放不进入当前里程碑。
- **漫画（Komikku 参照）**：多源搜索/详情、书库与阅读历史、RTL/LTR/上下翻页/条漫滚动、离线章节、基础追踪。OCR 翻译、站点级自动更新策略和桌面专属整合不进入当前里程碑。
- **小说（Mixn 参照）**：LK/LNS 双源能力契约、书库/进度/账号隔离、阅读器、下载缓存、EPUB/TXT 导出、备份与恢复边界。Mixn 的评论、签到、解锁等站点能力只有在已有适配器契约和真实接口证据齐备时才实现，不再因为“全量对齐”自动新增工作单。

## 暂缓项的处理结论

- **D59 JS 强隔离**：当前异步取消已完成；同步死循环需要独立 worker/进程协议，不能用 Dart isolate 或 QuickJS timeout 伪装完成。保留为架构任务，直到 Windows/Android 两端协议和打包方式确定。
- **D60 备份崩溃恢复**：运行期补偿已完成；跨 Hive/SQLite 的持久日志、启动恢复和并发导入串行化需要版本化日志格式。当前先冻结导入入口，不扩大数据模型。
- **D61 TTS/定位**：已实现按系统安全长度切分和滚动模式按块定位；逐词高亮、字符级 offset 和后台朗读仍明确不做。
- **D27/D38 与外部验收**：真实发布端点、物理设备、Windows C++ 工具链、真实账号和站点写入继续等待外部条件，代码任务不得把它们标成已完成。
