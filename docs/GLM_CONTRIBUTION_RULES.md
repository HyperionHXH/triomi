# GLM 工作边界与交付验收规则

更新时间：2026-10-05  
适用范围：所有由 GLM/DPSK 执行的 Triomi 工作单，尤其是 `D99-D105` 及其后续批次。

## 1. 角色和目标

GLM 负责简单、重复、可回归的工作：局部 UI、纯 Dart/Python 测试、解析器边界、文档整理和编码/无障碍回归。GLM 的交付是待 Codex 审核的变更，不是最终验收结论。

每个工作单必须先回答一个可观察的问题：用户完成了什么动作，应用显示或保存了什么结果，测试如何证明这个结果。只增加测试数量、改文案或让静态检查变绿，不算完成用户功能。

## 2. 可派给 GLM 的任务

- 已有协议和数据模型上的解析、校验、错误分类和回归测试；不得借测试改变协议语义。
- 已有页面上的加载、空态、错误重试、筛选、分组、启用/禁用状态和窄屏/无障碍修正。
- 来源目录和 Mihon 索引的展示层、下载状态和能力标签；可以展示“已下载/等待宿主”，不得展示“已安装可用”。
- 纯文档收口、证据链接、编码扫描和命令结果整理；历史事实必须保留，当前状态要注明证据层级。
- 不依赖账号、真实设备或新架构的本地测试。需要真实网络、Android 宿主、签名、DEX/ABI、播放器、跨存储事务或复杂桥接的缺口必须转回 Codex。

任务提示应写明允许修改的路径。未列入白名单的生产文件、依赖、数据库结构、规则协议和设备脚本不得顺手修改。

## 3. 明确禁止的结论和实现

- 不实现或模拟 `DexClassLoader`、Mihon `source-api`、`SourceFactory`、APK DEX 执行、签名安装或 ABI 兼容。
- 不把 APK 下载、索引解析、规则 JSON/JS 或 UI 开关写入 Triomi `SourceRepository`，也不声称它们已经能搜索、读章节或取图片。
- 不把 Bangumi 资料/搜索结果推导成番剧发现或播放源；不伪造 `content.playSources`、版权地址或真实站点结果。
- 不把本地 fixture、离线夹具、widget 测试、静态分析或已有历史日志写成真实联网、模拟器、物理设备、账号或播放验收。
- 不通过删除断言、跳过测试、放宽校验、修改夹具或吞掉异常来制造“全绿”。失败必须保留并记录。
- 不擅自扩展到 OCR、推荐算法、社交、DLNA、一起看、Anime4K、后台架构、任意 JS 隔离或其他未派发功能。

违反上述边界时，停止该子任务，保留最小复现或文档说明，并把问题交给 Codex；不要用替代实现掩盖缺口。

## 4. 工作流程

1. 开始前读取当前批次、最近审查文档、相关 ADR 和工作单，确认生产代码与测试的现状；不要依据旧交付摘要推断当前实现。
2. 在允许路径内先完成一个可观察的用户动作，再补最小且有意义的回归测试。测试应验证行为、错误状态或数据边界，而不是逐行重复实现。
3. 运行与任务相关的命令。命令必须来自本次执行，记录工作目录、环境/版本、退出码和测试数量或摘要。
4. 分开记录证据层级：离线/纯单测、widget/集成、真实网络、Android 模拟器、物理设备、真实账号。较低层级证据不能代替较高层级证据。
5. 交付前检查 diff 是否越过白名单、是否引入凭据或绝对路径、是否留下过时结论。不要自动提交或覆盖他人未提交改动。
6. 写完交付文档后停止在工作单边界，等待 Codex 审 diff、重跑检查并决定是否接收；GLM 不得把自评写成“审核通过”。

## 5. 交付文档模板

每个任务写入对应的 `docs/delivery/Dxx.md`，并使用下面字段。没有执行的命令写“未执行”和原因，不能填猜测值。

```text
任务：Dxx / 任务名称
目标用户动作：用户从哪里进入，执行什么动作，预期看到或得到什么
修改文件：逐项列出实际修改路径；说明是否只在工作单白名单内
实现结果：描述当前代码真实提供的行为；明确未实现的宿主/协议/设备能力
验证命令：完整命令、工作目录、环境/版本、退出码
验证结果：测试数量、关键摘要、失败用例；区分离线/widget/联网/模拟器/实机
证据路径：截图、日志、JSON 或其他可复查文件；不得记录 token、密码或 AppSecret
未完成/阻塞：准确写出缺口、复现方式和阻塞条件，不以“测试全绿”代替
交给 Codex：需要复杂实现、真实环境复验或最终决策的事项
```

推荐使用明确措辞：

- “索引解析和下载状态 UI 通过离线/widget 测试；APK 执行未实现。”
- “本机没有在线 ADB，未完成模拟器验收。”
- “Bangumi 条目可作为资料搜索结果；没有 `discover`/`playSources`，不宣称可播放。”
- “本批无新增回归；Codex 尚未审核接收。”

避免使用“插件可用”“真实源通过”“全部完成”“无阻塞项”等无证据或会掩盖边界的表述。

## 6. D99-D105 快速检查

派发 D99-D105 前，任务负责人应逐项确认：

- D99/D100：展示仓库、筛选、下载和启停状态，但明确等待 Triomi Mihon 宿主。
- D101/D102：分组和 Bangumi 边界正确；资料源不能进入真实番剧发现/播放来源。
- D103：覆盖缺字段、非 HTTPS、重复包名等输入；不把下载等同执行。
- D104：只修正文档事实和证据层级，不把历史日志冒充本轮结果。
- D105：只处理卡片溢出、开关语义和最小触控高度，不触碰播放器、规则协议或阅读器。

任何一项需要 Android DEX/ABI、来源执行器、真实站点账号、模拟器或物理设备才能证明时，交付文档必须标为“待 Codex/环境复验”，并附当前可复现的本地证据。
