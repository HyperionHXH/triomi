# ADR 2026-10-05：发现优先与阅读书架边界

状态：已决定

## 决策

Triomi 的主导航固定为：

1. 发现
2. 书架
3. 追番
4. 我的

发现页是默认首屏。书架页定位为“阅读收藏库”，集中管理漫画订阅、小说收藏、阅读进度、未读章节和离线内容。追番页保持独立，负责动画追踪、时间表、剧集进度和可用播放线路。

书架默认筛选只包含漫画和小说。动画详情提供「加入追番 / 已追番 · 取消」，保存到本机追番列表，不要求远端账号。追番页默认显示「我的追番」，用户切换到「放送表」时才加载网络时间表；`/tracking` 是远端追踪账号设置，不是本地追番列表。

2026-10-05 D91 收口：阅读书架与本地追番共用物理收藏表 `LibraryEntries`，通过 `MediaType` 分成两个业务视图。「不得写入阅读书架」指不得进入默认漫画/小说视图，不是禁止动画写入物理表。旧动画收藏直接出现在「我的追番」，保留原复合键、加入时间、观看进度、缓存目录与历史；无需一次性搬迁或新增表。兼容筛选「番剧（旧）」继续保留，它读取同一份动画收藏数据，也会显示新加入的动画。

重复收藏为幂等操作，不重置进度和未读数。默认阅读书架的「全部标为已读」只处理漫画/小说，显式分类只处理当前类型，避免清掉动画状态。取消追番只移除收藏关系，保留缓存和历史。

## 原因

用户进入聚合应用的第一意图通常是寻找新内容，因此发现页应先于管理型页面。漫画和小说都以阅读进度为核心，合并书架可以减少重复入口；动画具有时间表、逐集观看和播放线路等独有状态，继续放在独立追番工作区能避免书架筛选语义混乱。

## 影响范围

- 路由初始位置和四栏导航顺序需要更新。
- 书架筛选默认范围改为漫画/小说，仍保留显式兼容查看番剧的能力。
- 动画详情提供本地追番动作；远端追踪绑定继续是独立可选功能。
- 数据库表结构不变，`(sourceId, remoteId)` 复合键和既有缓存、历史数据继续有效。
- 文档、widget 测试和模拟器 smoke 验收路径需要同步更新。

## 不在本决策内

本决策不新增来源、不改变 Bangumi 资料源语义，也不把 fixture 视频当作真实番剧播放能力。真实 provider 和网络端到端验证仍按 D87/D90 记录。
