# ADR 2026-10-05：类别独立、封面网格与APK来源边界

状态：历史决定。混合发现/书架与“番剧（旧）”UI由[四工作区ADR](ADR-2026-10-16-four-independent-workspaces.md)替代；来源真实性、APK签名及以下历史证据保留。R165按用户明确要求以随包Suwayomi兼容运行时替代旧Windows不执行扩展的产品限制，边界见四工作区ADR。

## 决定

覆盖旧导航ADR中「书架默认全部漫画/小说」的部分：发现只保留番剧/漫画/小说，默认番剧；阅读书架只保留漫画/小说/番剧（旧），默认漫画。两处不再显示「全部」筛选。仍共用物理收藏表，追番是独立工作区，保留旧数据，操作仅作用于当前类别。

发现独立使用封面网格，正常手机三列、极窄两列、宽屏自适应；不继承书架列表设置。标题两行，来源行单独布局；分类/来源按钮按字体自然增高并能横向滚动，点击高度至少48dp。布局参考本地Kazumi源码，设备验收使用Triomi实际画面。

默认启用真实来源；本地夹具只在 debug 且 `--dart-define=TRIOMI_DEV_FIXTURES=true` 时参与运行。保留旧记录但不把夹具当真实来源；播种不能覆盖用户已安装/禁用的规则。

用户仓库属于Mihon/Tachiyomi APK生态，增加Android原生APK宿主作为明确核心工作，而非继续扩充无关功能。JS规则与APK扩展是不同来源类型。APK运行必须通过签名/包/lib校验、稳定64位字符串身份、真实DEX/source-api调用和整个阅读流程验收。目录展示、下载APK、JS版MangaDex均不等于APK兼容完成。

历史Windows方案暂不执行DEX，继续使用JS来源；R165改为应用私有的Suwayomi/Java兼容宿主，Android原生宿主不变。桌面JAR身份独立于APK签名确认，不以目录展示、APK下载或JS来源成功代替真实插件执行验收。

## 影响与验收

无需迁移数据库或清应用数据。旧导航ADR其余追番、历史与复合键约束继续有效。发现测试覆盖两倍字体、类别切换与过期响应；MangaDex目录完整性、图片信封与重启续页均有真实代码/设备证据。

依据：[C107–C108验收](../delivery/C107_C108_DISCOVER_MANGA_ACCEPTANCE.md)、[用户仓库调查与C110–C113验收](../delivery/C109_MIHON_REPOSITORY_AUDIT.md)。Android Mihon 宿主已完成首批真实扩展闭环；能力清单只覆盖已验收扩展，不把全仓库来源勾为完成。

C150历史APK备份兼容：早期宿主已保存package/versionCode/SHA256/完整signer pin，却未保存显示versionName；不能因此导出失败，也不能从可编辑偏好伪造版本名。只对缺该字段的已安装候选快照执行既有静态签名检查，字节hash及原包身份全部相等后取实际版本名，继续原portable清单校验。只inspect一次，不执行DEX，不改原信任或写回旧设置；缺其他身份、已存在但错误版本名、未验证平台仍拒绝。原设备正常五APK导出与消费者回归见`C150-final-acceptance.json`；完整原备份不强行并入另一原设备，限定APK运输验收明确记录派生范围。

后续C150实跑：原五APK正常导出，完整原件在API26只预览取消；明确标名的Webtoons-only派生包经正常SAF恢复，冷启仍停用待确认、先拒绝后显式确认实际完整指纹，DEX返回七语言且仍停用，手动启用后真实Feed/169章详情可达。结束只清自有新增，双设备原业务身份/状态指纹及原native pin完全一致。限定运输不是未经裁剪整库跨设备合并，封面占位不计通过，见`C150-apk-restore-final-journey.json`。

C151来源交互：分类是导航而非可清除的可选筛选；列表、失败、规则目录与新增入口严格按番剧/漫画/小说隔离，查询/语言/内容偏好按类别保存。番剧采用规则仓库流程，漫画APK管理分已安装/浏览/仓库，小说突出站点账号；已安装从本机pin/状态读取、不因远端索引失败消失。手动JSON导入仍是高级入口，以规则真实声明分类并跳转，不伪造类型。次要设置/验证/移除进菜单，启停保持显式并串行。旧开发夹具仅在正式UI隐藏、不删除原数据。
