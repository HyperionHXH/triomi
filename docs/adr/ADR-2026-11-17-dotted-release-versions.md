# ADR：点版本发布号与单端构建号

日期：2026-11-17。状态：用户已批准，R194 起执行。实际构建与发布结果只见 CURRENT_STATUS 与 delivery 证据。

## 决策

跨 Android 与 Windows 一起发布的更新只用点版本，例如 `0.16.0`，标签 `v0.16.0`。版本号不再附加 `+N` 之类后缀出现在版本名、标签或用户可见文案里。

只有真正单端更新时才追加构建号：先双端发过 `0.16.0`，之后只修桌面端，则发布 `0.16.0+2`。判断依据是本次改动影响的平台集合，不是发布次数。

## 实现约束

`pubspec.yaml` 仍需 `version: <点版本>+<构建号>` 形式，因为 Flutter 用 `+` 后面的数字作为 Android `versionCode` 与 Windows MSI/更新清单的比较依据。该构建号单调递增、只用于安装器与更新比较，不作为版本名呈现：GitHub 标签、应用内显示和发布标题都用点版本。

跨平台发布时点版本递增、构建号同时递增，两者不必相等，也不允许回退。单端追加时点版本保持不变，构建号继续递增。

## 理由

用户希望版本读起来是 `0.16.0` 而不是 `0.16.0+201`；同时更新检查、MSI 升级和 APK 覆盖安装需要不可回退的整数来比较，删掉构建号会让同一点版本的两次构建无法区分。把两条需求分开——对外只认点版本，对内保留构建号——既满足可读性，也不牺牲安装器语义。
