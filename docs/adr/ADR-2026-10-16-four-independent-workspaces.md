# ADR：四个独立内容工作区与按需来源执行

日期：2026-10-16。状态：用户已批准，R153实施。实际验证与发布状态只见 CURRENT_STATUS。

## 决策

主导航为追番、漫画、小说、我的。各工作区独立拥有搜索、筛选、分页、页面栈及收藏视图；漫画参考Android `komikku-app/komikku`，不是GNOME同名软件。追番内推荐/时间表/我的追番，漫画内书库/更新/浏览，小说内分站发现/全部与已下载书架。R161按用户新要求替代原“账号集中我的”：各内容设置及站点账号从对应工作区齿轮进入，我的只保留记录、下载、备份和通用维护。

本决策替代2026-10-05发现优先ADR的旧导航和漫画/小说混合书架，以及类别网格ADR的“番剧（旧）”UI。旧动画收藏不删除、不自动合并，在追番中保留来源身份与进度。

物理SQLite、来源宿主、下载、读器、播放器和安全存储继续复用。分类拥有固定媒体范围，旧混合分类通过增量迁移拆成独立定义；旧空分类/隐藏状态/动态规则/成员保留，备份恢复使用同一迁移约束。界面分离不等于复制数据库或凭据。

公开番剧资料、播放站作品、站内播放列表与剧集继续是不同身份。快照/本地缓存先展示，资料与播放目录独立刷新；镜像按实际公开接口和格式适配，不向第三方镜像转发账号凭据或受保护写请求，不复制上游签名密钥。

来源管理只读取元数据；已启用JS在第一次实际调用才初始化并核实导出能力，来源停用/移除/替换撤销执行实例，晚到结果不得发布。显式安装与升级继续执行必要的真实能力验证，APK签名与发布者确认策略不变。未核实的元数据不能被称为扩展已执行成功。

R155 导航修正：工作区入口及其搜索草稿仍在各自 StatefulShell 分支内；作品详情统一在 root Navigator 覆盖层打开，保证从统一历史、下载与关联作品进入后返回原入口。详情中的标签搜索和搜索结果的来源目录作为 root MaterialPageRoute 子流程打开真实 SearchPage/MangaSourcePage，不再向已有 root 覆盖层 push 第二个相同 StatefulShellRoute。否则 go_router18 会重用分支 Navigator 页面键，实际出现无标题空白页。此决定不新增兼容路由、不复制页面实现，也不清工作区搜索状态。

R161 进一步分离呈现而非复制业务：番剧使用播放来源与列表选集，漫画使用连续懒构建章节列表，小说使用真实分卷目录。共用详情加载、身份、缓存及读器入口；长目录不通过任意50章范围分页或嵌套滚动绕过布局。稀有菜单只保留实际支持的类型操作，小说仍可正常进入来源解锁界面及同类型换源，不因精简菜单删除已有能力。

三类离线下载均先显式选择章节；取消不入队，目录快照仍完整保存。队列只接受当前作品来源的未锁定有效章节键，避免不同来源同remoteId串号；番剧单次选择一个播放列表，切换列表清空选择。轻书架逐章缓存沿用正常阅读授权并保留专用字体，不等同官方整书文件下载，不调用金币下载接口或重新打包受限整书。WebDAV 收藏与历史同步、全应用备份复用连接，但分别保存并明确展示操作范围。

进度追踪按本地媒体类型搜索及管理绑定，服务凭据仍共用原安全存储。Bangumi动画分类为2，漫画与小说同属书籍分类1，界面明确核对版本，不虚构远端子类型；AniList按ANIME/MANGA及NOVEL格式区分。类型独立不改变真实站点权限或备份凭据边界。
R165桌面入口与手机保持四个工作区；取消宽屏单独的第五个设置导航，通用维护从我的进入。窄高窗口侧栏允许滚动，右键复用触屏长按操作。时间表当前周仍一次取得完整七天，列表只做视口懒构建，不做三部截断；切换星期与筛选重置滚动位置，避免沿用上一天尾部位置被误认为只加载少量。

按用户要求，Windows扩展改为随包私有Suwayomi v2.4.2366与Java21，不依赖用户的外部服务器或Java安装。原始上游JAR以固定SHA-256分片打包并重建校验，保持更新器原单成员128MiB限制。APK通过静态apksig验签；有配套桌面JAR时检查包名/版本等元数据，单独展示来源URL和SHA-256供确认，运行时实际执行文件必须匹配确认指纹。无配套JAR可尝试上游APK转换，不因兼容失败关闭Java验证。

私有JVM通过Windows Job拥有，应用退出终止子进程；仅本地回环、随机端口和每次新认证，禁用WebUI/KCEF/浏览器自动打开/上游自更新。启动前核验已保存原件及执行文件，隔离未登记/改变的JAR；启动后先恢复安装事务，再允许来源调用。安装失败先终止可能仍执行的上游协程，重启核验恢复，不在不确定服务器上重放旧版本。静态核验Java有独立生命周期和45秒期限，状态文件原子替换且串行发布。仍不是不同UID/权限沙箱，不对全部插件或网页挑战做兼容承诺。


## WebDAV 内容同步与来源恢复

对照 [Kazumi WebDAV](https://github.com/Predidit/Kazumi/blob/57d13399df3f34641a1b3100822671e8c545cf30/lib/services/sync/webdav.dart)：上游分别同步收藏、观看历史事件和弹幕屏蔽规则，WebDAV 不负责替代 Bangumi 账号 API。Triomi 使用独立 `library.v1.json` 同步漫画与番剧的收藏、取消收藏、普通逐章观看记录、页码或秒数、续读章节和已确认的番剧播放站关联；完整 ZIP 备份继续独立。旧 `anime-follows.v1.json` 只有一次性只读迁移，不保留第二个远端写入器。

作品、章节和播放站使用完整来源限定键，不按名称自动合并。收藏有独立于播放进度的版本时钟与删除记录，持续播放不能撤销另一台设备的取消收藏；阅读记录按最近访问而非最大页码合并，秒级数据库时间精度下的连续操作仍严格递增。单作品、媒体类型和全部历史清空均保留有界删除标记，后续新阅读可以恢复；取消收藏本身不清历史。不上传隐私历史、图片、视频、下载内容、APK/JAR、规则代码、请求头、Cookie、密码、信任或可播放媒体地址，只保留必要的作品/章节页面元数据；不会覆盖本机已缓存正文。每个来源仍在本机独立安装、信任、登录或配置。

同步先验证完整文档及身份图，以同一 ETag 约束读取和条件上传，再在本地事务中检查账户、配置和本地快照是否仍匹配。冲突、损坏、类型串号或超限均失败，不截断、不覆盖。文档限制为 8 MiB、2 万收藏状态、5 万作品/历史/续读章节/关联等各类记录；只携带历史和选集引用的章节，不复制整部作品目录。仓库地址、插件包名和来源名只是未受信提示，不能自动添加仓库、安装、启用或执行插件。

缺源提示只读取本机来源元数据：区分未安装、已停用和已安装但不可用，展示准确来源身份并进入带名称/包名搜索的真实插件库。找不到插件时，参考 [Komikku 迁移搜索](https://github.com/komikku-app/komikku/blob/master/app/src/main/java/eu/kanade/tachiyomi/ui/browse/migration/search/MigrateSearchScreenModel.kt)，在用户主动操作后并发搜索同类已启用来源，每次最多四站，结果与失败渐进显示、可取消。用户核对作品及章节后才复制记录，保留原记录；不同来源从确认章节开头续读，不照搬页码或秒数。仅有历史、未收藏的作品也能迁移，且不会被隐式加入收藏。番剧缺少原播放站时仍保留资料作品身份，提示针对实际播放来源。

WebDAV 密码和追踪令牌只存本机安全存储；旧 Hive 凭据仅在安全写入成功后移除。非回环 HTTP 必须对该地址显式确认明文风险，换地址重新确认；携带凭据的 DAV 请求拒绝重定向。HTTPS 保护传输，不等于端到端加密，WebDAV 服务端仍能读取同步元数据。Android 规则浏览器 Cookie 按用户明确保存的来源 ID 与主机授权，不能借用其他来源的全局登录会话。公开 Bangumi 镜像切换不再销毁运行中的来源与 JS 实例。

R175 自动同步：应用启动/恢复前台、收藏或普通历史变化后运行同一合并器，不要求用户上传 ZIP。变化静默10秒合并、持续变化最多等待30秒，前台每3分钟探测；手动操作加入同一在途任务，暂停后台只尽力提交未保存变化，不承诺被系统终止后后台执行。认证/格式错误停止自动重试，瞬态失败有界退避，本机读写不等待网络。连接状态由认证 PROPFIND 的有效 DAV 目录响应确认，保存配置或文件404不算连通。Bangumi 收藏自动同步独立选择，先合并 DAV、再同步账号、最后回写 DAV；精确页码/秒数仍由 DAV 保存，Bangumi失败单独呈现且不撤销DAV成功，不远端删除用户收藏。

完整备份保持独立且由用户确认。封面最多4并发；编码、压缩和ZIP写入在独立isolate中执行，逐文件开关句柄，取消等待工作线程退出并清理暂存；离开页面继续由应用级操作持有。上传使用显式v2版本清单及最多64MiB文件块，按实际剩余字节分配；保留v1清单读取，旧客户端不支持v2，应先升级或使用普通ZIP导出迁移。集合创建仅每次操作一次，复用块流式校验，版本头继续以ETag CAS提交。新清单不改变ZIP内部的data.json、covers/media与完整性校验格式。坚果云免费版每30分钟600请求的官方约束见[帮助中心](https://help.jianguoyun.com/?p=2064)，不将分块改为无限并发或逐播放心跳写云端。

## 用户操作

R155 以插件管理简化漫画浏览：已安装/浏览/仓库及单一插件名称搜索；已启用来源仍进入真实单源目录。单源浏览和全源搜索保留真实插件 hasNextPage 与 FilterList 语义，三个内容搜索互不越界，各来源结果渐进显示。旧订阅配置保留数据，但不再成为浏览主入口。

筛选采用分组、有分界的草稿面板和选择式题材标签；应用才请求，取消无副作用。没有跨内容类型筛选或番剧格式下拉。次要操作进更多菜单，批量动作只在选择模式出现并受固定模块范围限制。

## 验证纪律

优先运行真实用户路径、请求与文件/播放消费；不能用就修。并行实现期间不为每个小改重复全量测试/构建/格式化；集成后集中执行必要行为回归、数据迁移、签名、保数据升级和Release资产检查。不通过固定文案/默认值测试或隐藏异常代替可用性，不把历史证据冒充当前构建成功。

## 仍有效的既有约束

所有内容继续以(sourceId,remoteId)为业务键；来源认证隔离，备份不带凭据与信任；LNS字体和下载权限保留。Android使用原生APK宿主，Windows使用上述受管兼容宿主，其他非Android平台仍明确不支持。原生播放/后台、来源升级事务、备份补偿和HLS数据完整性继续保留。R155按用户要求移除隐私锁/无痕和小说朗读产品功能，保留原业务数据与系统无障碍语义。

完整交互和迁移理由见 [R152大纲](../REFACTOR_OUTLINE_FOUR_MODULES.md)。
