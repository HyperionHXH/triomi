## 改进点（对齐工作单要求）

1. **消除固定 5 秒等待**：原单任务用例的 `waitFor(queued==0 || calls>=breaker)`
   在修复后的实现上永远等满 5 秒超时（正确实现下任务不会 done、调用数
   不会到阈值）。改为 `awaitCallsStable`：以 120ms 为窗口轮询调用数，
   连续一个窗口不变即判定「泵已停」——正确实现约 0.2 秒返回；自旋实现
   每个窗口都在增长，直到熔断器（25 次阈值，**保留**）翻网排空队列后
   才稳定（≤1.5 秒）。两种终局都快速终止，断言严格区分（queued==1 且
   calls < breaker 才算通过），**没有用放宽断言换速度**。
2. **开关关闭时恢复队列**：新增用例——非 WiFi + 停泵后，用户把
   「仅 WiFi」开关关闭（网络不变），显式 `resume()` 后队列照常执行到
   done，且 wifiOnly=false 时 run 短路（调用数不再增长，与停泵时一致）。
3. 多任务停泵用例同样改用稳定信号（消除 2×300ms 固定等待）。
4. 无自旋证明：新增断言「关闭开关后调用数封顶在停泵水平」+
   原有「停泵后调用数不再增长」断言保留。
