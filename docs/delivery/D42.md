## 审计结论

错误文本进入 UI（snackbar / 状态行）与日志的三个入口——

| 入口 | 错误构造路径 | 脱敏状态 |
|---|---|---|
| 导出（`detail_page._export` → `导出失败：$error`） | 来源取数失败 → `SourceException`；网络层失败 → `DioSourceHttpClient.send` → `SourceException.wrap(url: …)` | ✅ wrap 统一脱敏（D22-1 修复），本轮补回归 |
| 备份（`backup_page` / WebDAV 同步） | `WebDavClient` → `http.send/uploadBytes/fetchBytes` → wrap(url: fileUrl) | ✅ 同上；Basic 凭据只在 Authorization 头、不进 URL（约定固化） |
| WebDAV 状态行（`webdav_page`：`检测失败/上传失败/拉取失败：$error`） | 同上 | ✅ 同上；用户把账密粘进 baseUrl 的场景由 userinfo 剥离兜住 |

本轮确认 Codex 的 D22-1 修复（`SourceException._safeUrl` + `sanitizeMessage`）
在三条入口全部生效；本任务把行为固化为网络层契约回归，并补齐此前没有的
`SourceException.wrap` 直接单测（js 生命周期用例只覆盖了 JS 桥一条间接路径，
且原 d22-1 回归现随修复转绿，已验证）。

## 覆盖清单（10 例）

**`SourceException.wrap` URL 脱敏**（7 例）：
- query 里的 token 不进错误文本、URL 主体保留；
- userinfo（`user:pass@`）剥掉（用户把 WebDAV 账密粘进 baseUrl 的兜底）；
- fragment 剥掉、端口保留（连接信息）；
- 非标准 URL（无 scheme/host）保守取 `?`/`#` 前的路径段；
- 错误详情内嵌 URL（重定向提示等）同样脱敏；
- 无 URL 的错误原样保留（`Exception:` 前缀保留，不破坏可读性）；
- 已是 `SourceException` 的错误原样返回（契约保留，不二次处理）。

**真实网络层**（1 例）：`DioSourceHttpClient` 对 `127.0.0.1:1`（保留端口、
立即拒绝、不触外网）的连接失败 → wrap 后文本带路径但剥掉 query 凭据、
归类 network。

**消费方契约**（2 例）：WebDAV 的 Basic 凭据只在头里不进 URL（约定固化）；
导出失败的 `userMessage` 不含凭据且分类标签在前。
