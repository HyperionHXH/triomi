# D35 备份导入补偿一致性

## 完成范围

`BackupService._apply` 现在先快照并导入允许的设置键，再在 Drift transaction 中导入业务数据。设置写入中途失败会删除本次新增键并恢复旧值；数据库事务失败也会执行同一补偿，Drift 自身负责回滚数据库写入。这样不会把“数据库已提交、Hive 只写了一部分”作为正常结果暴露给用户。Hive 与 SQLite 仍没有物理共同事务，进程在补偿窗口内被强杀时只能依赖下次恢复/校验。

`Preferences.restoreSubset` 是最小补偿接口；敏感键和排除前缀仍在导入前过滤。D33 回归已更新为验证失败后设置恢复、既有数据库记录保持不变。
