## 覆盖清单（14 例）

**run() 任务状态机**：
- 来源不可用（provider null）→ failed + 「来源不可用」，不计已下载；
- 锁定章节 → failed + 「付费」，正文不入库（红线：不缓存）；
- 空正文 → failed + 「正文为空」；
- 小说成功 → done + `localChapterContent` 可读；
- 图片中途失败 → failed、不计已下载；失败任务的目录不对外暴露
  （`localImageDir` 只认 done，第一张图虽落盘也不构成可读离线内容）。

**排队与重试**：
- done 后重复 enqueue → 同一任务保持 done（不重排）；
- failed 后 enqueue → 重新排队（markQueued），来源恢复后重试成功转 done；
- 两来源相同章节 ID（`lk/3001` vs `lns/3001`）→ 两条任务、离线正文互不串源。

**离线一致性**：
- done 记录目录缺 manifest → 不可读；manifest 损坏 JSON → null（不抛错）；
- `removeFiles` 只删传入行拥有的路径；path 为 null 安全跳过；清单外文件不动；
  只删文件不动记录（记录删除由调用方决定）——跨目录删除的保护来自
  「rows 来自本作品的任务行、path 由本应用写入」这一信任边界，
  测试固化了清单外文件不受影响；
- 调度竞态：对已删除任务回写状态（迟到的失败/完成回执）是安全空操作，
  不抛错、不重建行。

**仅 WiFi**：
- wifiOnly 关闭 → 不做网络判断照常执行；
- wifiOnly 默认关闭（降级语义：取不到设置不阻塞用户）；
- **限制记录**：`DownloadService.isOnWifi` 是静态直读网络接口，测试进程无法
  注入接口列表，`wifiOnly=true + 非WiFi` 的 markQueued/停泵分支无法确定性
  触发——该分支交设备/本机验证（工作单预期内的限制，未模拟全机网络）。

### D19-1（P1）目录缺失时 run() 标 done 但离线正文静默丢失

- **测试**：`目录缺失时 run 标 done 但正文静默丢失（缺陷回归，当前失败）`
- **触发**：下载任务对应的章节行不在 `chapters` 表（例如目录缓存被清/导入
  恢复不全）时执行 `run()`。
- **预期**：任务不标 done，或正文落库可读。**实际**：`run()` 在
  `chapterOf` 为 null 时合成章节继续执行并 `markDone`，而
  `saveChapterContent` 只 UPDATE 已有章节行 → UPDATE 匹配 0 行，内容丢失，
  任务却显示已完成（`doneChapterIds` 也计入）。
- **影响**：离线列表显示「已下载」但打开无正文。
- **建议**：`run()` 中 `chapterOf == null` 时按来源不可用处理；或
  `saveChapterContent` 改为 upsert。生产代码改动归 Codex。
