## 覆盖清单（10 例）

**握手与连接循环**：
- 握手超时：抛 network「连接轻书架超时」，下一次调用重建全新连接
  （`identical` 断言 socket 换新），补握手帧后调用成功；
- 握手失败（error 帧 Unauthorized）→ auth，之后第二次调用自动重新建连并成功
  （建连带 `access_token` query 与 Bearer 头——复用 T4 的断言方向）；
- reset 让在途调用按「轻书架连接已重置」失败；失败后重建连接并成功
  （编号不回收：重建后的调用是第 2 号）；
- 旧连接的关闭事件不能击穿新连接：旧 socket 在新连接建立后才 emitClosed，
  新连接的调用照常完成（`_failConnection` 的 `identical(_socket, failedSocket)`
  守卫）。

**完成帧的防御**：
- 超时后迟到回执：被忽略，不误完成其他请求；invocationId 编号不回收
  （超时的调用结束后，下一次调用拿 2 号，避免歧义）；
- 未知 ID（999 ghost）与重复完成帧：只第一次回执生效；
- malformed JSON 帧：静默忽略，连接保持可用（后续调用正常）；
- 二进制帧：按 UTF-8 文本解析（SignalR 二进制协商未启用）；
- type 7 关闭帧：在途调用失败；`Unauthorized` 归 auth、其余归 network
  （`_hubError` 分类）。

## 重连与非幂等调用的明确答案（交付要求）

连接层**从不自动重发**任何调用：reset/关闭/超时只会让在途调用失败，
下一次 `invoke` 才会重建连接并作为新调用发出。全库只存在两个显式的一次性
重发点，都在连接层之上：

1. `FallbackLnsHubConnection`（`lns_hub_connection.dart:331`）：主端**网络
   错误**时把同一次调用在备用 Hub 上重发一次（仅一次，备用也失败就抛）；
2. `LnsGateway._invoke`（`lns_gateway.dart:510`）：收到 **auth** 错误时刷新
   会话后重发一次（仅一次，`retried` 标记防循环）。

因此**非幂等调用（SignIn 签到、SaveBookShelf 写书架）在「主端网络错误 →
备用端」路径下确实会被重发一次**——这是现行明确契约：主端失败意味着请求
结果未知，备用端重发是最接近站点行为的选择（Mixn 同款）。没有无限重放、
没有静默多次重试；签到类调用是否接受这个一次性重发由调用方（未来如加
「避免重复签到」的幂等键）决定，本任务不凭空要求重放或禁止重放。

### D21-1（P2）reset/连接失败后底层 socket 永不关闭

- **测试**：`reset/握手超时后旧 socket 未被 close（缺陷回归，当前失败）`
- **触发**：任何触发 `_failConnection` 的路径（`reset()`、onDone、onError、
  type-7 帧、握手超时）。
- **预期**：旧 socket 被显式 `close()`。**实际**：`_failConnection` 只
  `subscription.cancel()` 并把 `_socket` 置 null（`lns_hub_connection.dart:305`
  起）——取消订阅不等于关闭 WebSocket，真实连接会保持打开直到 GC。
- **影响**：频繁 reset（登录/换源）或握手超时的会话会在服务端悬挂连接；
  长会话里是 fd/内存压力。测试替身上表现为 `closed == false`。
- **建议**：`_failConnection` 在取消订阅后调用 `unawaited(oldSocket.close())`
  （捕获 close 自身的异常）。生产代码改动归 Codex。
